# 瓦罗兰 · 本地维护入口

项目目录统一为 `src/瓦罗兰`。导入酒馆的卡名沿用已确认的“瓦洛兰”，本地构建产物位于 `dist/瓦罗兰`。

`世界书/index.yaml` 配置发送给模型的条目；`世界资料来源.yaml` 单独组织地点与组织资料。后者引用的地区 YAML、组织与场所 Markdown 是生成源，即使没有作为触发条目启用也需要保留。

`schema.json`、运行目录下的地图/世界资料 JSON、世界书 JSON、PNG 与 `dist` 是派生产物。修改时优先编辑维护源。

## 常用操作

以下命令在仓库根目录运行。先生成资料与规则，再打包；普通打包不会上传 GitHub。

```powershell
node src/瓦罗兰/工具/生成派生产物.mjs
node src/瓦罗兰/工具/生成规则类型.mjs
node src/瓦罗兰/工具/构建角色资源.cjs
node src/瓦罗兰/工具/打包世界书.mjs
node src/瓦罗兰/工具/打包本地角色卡.mjs
```

本地开发双击 [启动本地监听.cmd](启动本地监听.cmd)，或执行 `node src/瓦罗兰/工具/启动本地监听.mjs`。5500 提供当前卡的静态资源，6621 通知热更新。三个项目脚本与角色名录均使用 `dist/瓦罗兰`。修改世界书后需要重新打包并导入卡内世界书。

常用检查集中在 `测试/`；`工具/` 只放构建、生成和打包工具及其依赖。

```powershell
node src/瓦罗兰/工具/测试.mjs
node node_modules/typescript/bin/tsc --noEmit -p src/瓦罗兰/工具/tsconfig.json
node src/瓦罗兰/工具/构建.mjs
```

测试入口逐文件使用独立进程，避免测试夹具的全局状态互相干扰，以及 Node 测试子进程通信错误。需要保存结果时可加 `--report=结果文件.json`。

重新打包正式 PNG：`node src/瓦罗兰/工具/打包当前正式版.mjs`。正式 PNG 从当前世界书源打包，引用已发布资源。发布代码前需要重新正式构建并做远端核验，详见 `发布/当前/README.md`。正式构建读取 `发布/配置.json` 中的公开角色名录；上传需要明确调用发布工具。

## 保留的兼容接口

远端 `澄湾日常/frontend-current.json` 及固定提交资源路径继续有效。`澄湾设置`、`澄湾角色库` 等存档键、角色包格式标记、`chengwan:*` 事件和现有脚本 ID 也保留，供已有聊天、角色包和正式卡继续使用。这些属于兼容接口，不是旧世界设定。

角色库停用快照保存在聊天变量中；转移存档时应保留完整聊天及聊天变量。正文与手机分别使用对应变量 API。未知人物事实保持未知，更新条件见变量规则。

清理前完整快照在仓库 `备份/瓦罗兰/目录整理前-20261002-190831.zip`，同名 JSON 保存逐文件哈希。历史报告、截图、旧发布包和一次性工具已从维护目录清理。整理记录见 [文档/目录整理.md](文档/目录整理.md)。
