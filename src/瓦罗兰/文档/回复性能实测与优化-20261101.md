- 已保存正文保留在第 2 层，`cw_update_pending=true`。原提交 ID 为 `action_aa54043d-3595-49f5-a3b2-71bb38afa605`。

## 已实施优化

1. **正文明确引用的资料直接展开**。原实现先用 `needsInformationSelection` 根据 ID/名称判断缺资料，再请求模型重新选择；随后本地 `ensureInformationContext` 又会按同一组明确引用展开。现在直接使用既有展开函数，保留第一次选择结果、手动“仅名称”和完整存档，再保存同一份 pending。正文前用于推断关联资料的选择 API 保留。本次样本原有的第二次资料请求耗时 5.287 秒；这是已删除调用的旧样本耗时，不是优化后总耗时实测。
2. **全部手动指定时跳过选择 API**。当所有现有地点、组织都被手动指定为“展开”或“仅名称”，模型无法改变最终投影，因此直接按现有覆盖处理。存在任意自动项时仍走原选择流程，不用“当前全展开”代替手动覆盖判据，不按相同输入跨轮缓存选择。
3. **合并前端重复读取**。`refreshMessages` 复用一次候选读取的数据及所选候选元信息，正文仍显示保存的 `message/mes`，不改用可能滞后的 swipe 文本。`activeContext` 复用相同读取中的元信息。原源检查、候选身份、保存、读回、恢复和原提交 ID 保留；800ms 编辑对账机制未删除。

业务改动仅涉及 `运行/host.ts`、`运行/knowledge-context.ts`。测试夹具补齐真实接口的 `swipes_info`，并将候选元信息写入当前候选，修正原来固定写第 0 项的夹具误差。

同一刷新样本的消息接口读取从 3 次降为 2 次，完整资料保留。增加变量失败重试、原提交 ID/单次计轮、组织展开、手动仅名称、保存原文与 swipe 不同步、所选候选元信息等验证。

- CJS 全套 **407/407 通过**，无跳过；这是隔离程序回归，不是整卡实玩验收。
- 正式生产构建完成，173 个输入哈希匹配；已有前端约 1.2 MiB 的包体警告仍存在。
- ESLint 当前 2 个错误；对修改前同路径源码使用相同检查复核，也有相同 2 个错误：未使用的 `envelope` 赋值、已有的错误 cause。此次未新增，不称为全项目静态检查零错误。
- 优化后没有再调用真实模型。不能给出优化后的真实总耗时或保证所有回复已恢复正常速度。

## 仍待定位

1. 正文网络完成后的 43.380 秒额外等待，需继续区分工具响应还原、流处理和事件完成时机；没有定位前不添加超时、重试或替换预设。
2. 同一轮观察到 **159 次全局设置保存**，单次请求体约 2.88 MB。调用栈经过 JS-Slash-Runner、匿名包装和 LittleWhiteBox，尚不能确认反复触发者及其因果贡献；没有修改其他插件。
3. 请求确实将主要上下文搬入工具描述，变量请求工具说明 105,230 字符，最终请求体 242,762 字节。只统计 messages 会低估输入。具体搬运触发方尚未证实，不能仅凭 `display_stream` 字段或函数名归因于 st-chatu8。字符、字节均不是供应商 token usage；本轮未取得可靠 usage。
4. 本次变量响应 JSON 语法错误仍保留为失败样本。没有通过宽泛清洗、丢弃错误、改写存档或降低校验来伪装结算成功。
